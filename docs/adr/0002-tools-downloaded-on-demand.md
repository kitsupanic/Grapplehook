# Tools are downloaded on demand, not bundled

Grapplehook does not bundle `yt-dlp`, `ffmpeg`, `ffprobe` or `aria2c` in its installer. When the user clicks **Install Tools**, it downloads them as Managed Tools into its app-data folder, and it falls back to System Tools on `PATH`. Bundled sidecars would make the installer 150 MB or more bigger. They would also freeze `yt-dlp`, which YouTube breaks often and which cannot self-update (`yt-dlp -U`) inside a signed app bundle.

## Consequences

- **ffmpeg must be a GPL build.** The H.264 transcode needs `libx264`, which LGPL builds lack. We use BtbN builds pinned to a release branch on Windows and Linux, and martin-riedl.de's `release` channel on macOS arm64. The README and About panel credit each Tool and link its source.
- **aria2c is a Managed Tool only on Windows.** aria2 publishes no official macOS or Linux binary, and we will not ship third-party builds that have no checksums. Elsewhere it is used only as a System Tool. Without it, downloads fall back to yt-dlp's slower built-in downloader.
- **Integrity comes from the checksum file published in the same release, fetched over HTTPS.** This catches corrupt or partial downloads, but not a compromised release host. We chose it over pinning hashes in each app release so that "latest" URLs keep working.
- **macOS Gatekeeper.** Gatekeeper does not check files that an app downloads without setting the quarantine flag. Checked on macOS 26 (Darwin 25.5), Apple Silicon, 2026-11-16: core's `install_tools` downloaded the real `yt-dlp_macos` (release 2026.10.26) over HTTPS into a fresh folder. `xattr -l` shows only `com.apple.provenance` (no `com.apple.quarantine`), and `yt-dlp --version` printed `2026.10.26` with no prompt. The binary is a universal Mach-O that upstream already ad-hoc signs (`codesign -dv`: `flags=0x2(adhoc)`), which is enough to run on arm64. `spctl --assess` says "rejected", as it does for any non-notarized command-line program, but it is not enforced without the quarantine flag. So no `codesign` or `xattr -d` step is needed. This was run from a test process, not the packaged GUI app; the by-hand check in the real app is still to be done.
